# autoshorts

**Free, automatic vertical short-video generator for TikTok and YouTube Shorts.**

Give it a topic (or let it pick one) and it writes a script, records a voice-over,
burns in animated word-by-word captions, lays stock or generated footage under it,
mixes in background music and renders a 1080x1920 MP4 together with a thumbnail,
titles, descriptions and hashtags. It can upload the result to YouTube and TikTok
and run on a schedule on your PC or a Linux server.

Every part of the stack is free: open-source tools, local models and free API tiers.
No paid subscription is required.

> **Before you plan on income:** autoshorts makes drafts quickly. It does not make a
> channel eligible for money by itself. Read [Monetisation - read this first](#monetisation---read-this-first).

## What it does

```
topic        topics.txt, --topic, or a built-in list of 216 ideas
  |
script       LLM (Ollama / free API) or the built-in offline bank -> hook, 6-10 segments, title, hashtags
  |
voice-over   edge-tts neural voices (online) -> pyttsx3 / espeak-ng (offline) + word timings
  |
captions     word-by-word ASS captions, active word highlighted, title banner (rendered by libass)
  |
footage      per segment: Pexels -> Pixabay -> your own clips -> generated animated backgrounds
  |
render       FFmpeg: crop/loop/zoom shots, burn captions, mix music ducked under the voice
  |
metadata     YouTube title/description/tags, TikTok caption, credits for stock footage
  |
upload       optional: YouTube Data API, TikTok Content Posting API (inbox draft or direct post)
```

Each video gets its own folder, `output/<YYYYMMDD-HHMMSS>-<slug>/`:

| File | What it is |
|---|---|
| `video.mp4` | the finished 1080x1920 H.264/AAC video |
| `thumbnail.jpg` | a frame from the video |
| `script.json` | the script as narrated |
| `captions.ass` | the caption file that was burned in |
| `metadata.json` | everything the uploaders send |
| `youtube.txt`, `tiktok.txt` | copy-paste ready title, description, tags, caption |
| `credits.txt` | creators of the stock clips used |
| `job.json` | status, timings, upload results |
| `error.txt` | only if the video failed: the full error |

Five script formats: `facts`, `story` (short, clearly fictional stories), `quiz` (question,
"three, two, one" pause, answer), `motivation` and `explainer`. `random` picks one per video.

## The free stack

| Stage | Default | Free alternatives | Notes |
|---|---|---|---|
| Script writer | `auto`: Ollama if running, else a free API key, else offline | [Ollama](https://ollama.com) (local), [Groq](https://console.groq.com), [Google AI Studio / Gemini](https://aistudio.google.com), [OpenRouter](https://openrouter.ai) `:free` models, built-in offline bank (33 scripts) | Any OpenAI-compatible API works. Without an LLM only the offline bank's topics are covered. |

| Captions | FFmpeg + libass | any font in `assets/fonts/` | Word-by-word with highlight and pop animation. |
| Footage | [Pexels API](https://www.pexels.com/api/), [Pixabay API](https://pixabay.com/api/docs/) | your clips in `assets/backgrounds/`, procedural backgrounds generated by FFmpeg | Works with no keys at all (generated backgrounds). |
| Music | your tracks in `assets/music/` | [YouTube Audio Library](https://studio.youtube.com) | Ducked under the voice automatically. |
| Render | [FFmpeg](https://ffmpeg.org) (libx264, AAC) | | CPU only; no GPU needed. |
| Upload | [YouTube Data API v3](https://developers.google.com/youtube/v3) (free quota) | [TikTok Content Posting API](https://developers.tiktok.com/doc/content-posting-api-get-started) (free) | Both need a one-time setup; see the limits below. |

A note on edge-tts: it is an unofficial client for the voice service behind Microsoft
Edge's "Read aloud". It needs no key and costs nothing, but it is not an official API.
It can break or get blocked without notice (autoshorts then falls back to the offline
voices), and Microsoft publishes no terms for using these voices in videos. If that
matters to you, set `tts.provider` to an offline engine.

## Monetisation - read this first

These facts were checked on **1 October 2026**. Programmes and thresholds change, so
follow the links before you rely on them.

### YouTube

- **YouTube Partner Program (YPP) thresholds today**
  ([YPP overview](https://support.google.com/youtube/answer/72851),
  [expanded YPP](https://support.google.com/youtube/answer/13429240)):
  - *Fan funding and Shopping:* 500 subscribers, 3 public uploads in the last 90 days, and
    either 3,000 public watch hours in the last 12 months or **3 million public Shorts views
    in the last 90 days**.
  - *Ad revenue sharing (including Shorts):* 1,000 subscribers and either 4,000 public watch
    hours in the last 12 months or **10 million valid public Shorts views in the last 90 days**.
- **Announced changes from 1 February 2027** (announced 10 August 2026;
  [Changes to the YouTube Partner Program](https://support.google.com/youtube/answer/12843009),
  coverage: [Search Engine Journal](https://www.searchenginejournal.com/youtube-updates-partner-program-terms-shorts-payout-rules/585331/)):
  - New applicants need 1,000 subscribers plus 8,000 watch hours in 365 days **or
    20 million qualified Shorts views in 90 days**.
  - Earning from the Shorts revenue pool needs 10 million qualified Shorts views in the
    trailing 90 days, checked every month. Channels already in YPP keep their membership,
    but a month below the threshold pays no Shorts pool revenue.
- **"Inauthentic content" is not monetisable.** On 15 July 2025 YouTube renamed its
  "repetitious content" policy to *inauthentic content* and clarified that it covers
  mass-produced or repetitive content: videos that look made from a template with little
  to no variation, or that are easily replicable at scale
  ([channel monetization policies](https://support.google.com/youtube/answer/1311392)).
  This is aimed exactly at channels that post unedited automated videos.
- **Disclose realistic altered or synthetic content.** YouTube requires disclosure when
  content that seems realistic was meaningfully altered or synthetically generated, for
  example a real person appearing to say something they did not, altered footage of real
  events or places, or a realistic scene that never happened
  ([disclosing altered or synthetic content](https://support.google.com/youtube/answer/14328491)).
  autoshorts sets the API's `containsSyntheticMedia` flag by default
  (`upload.youtube.contains_synthetic_media: true`) and adds a short text-to-speech/AI
  note to descriptions (`metadata.ai_disclosure: true`). Keep both on.
- **Music on Shorts longer than one minute.** Since 15 October 2024 vertical videos up to
  3 minutes count as Shorts, and a Short longer than one minute with an active Content ID
  claim is blocked and cannot earn
  ([three-minute Shorts](https://support.google.com/youtube/answer/15424877)). autoshorts
  aims for about 65 seconds, so only use music that cannot be claimed (see
  [music](#background-music)).
- **API uploads from unaudited projects are locked private.** All videos uploaded through
  `videos.insert` by unverified API projects created after 28 July 2020 are restricted to
  private viewing until the project passes an audit
  ([videos.insert](https://developers.google.com/youtube/v3/docs/videos/insert)). Such videos
  cannot be switched to public later; they must be re-uploaded through YouTube itself
  ([videos locked as private](https://support.google.com/youtube/answer/7300965)).

### TikTok

- **Creator Rewards Program**
  ([Creator Rewards Program](https://support.tiktok.com/en/business-and-creator/creator-rewards-program)):
  at least 18 years old, at least **10,000 followers** and **100,000 video views in the last
  30 days**, a personal account in good standing, in a country/region where the programme
  is available (the list changes; check in the app under Creator tools). Only **original,
  high-quality videos longer than one minute** earn. That is why `video.target_seconds`
  defaults to 65.
- **Label AI-generated content.** TikTok requires creators to label realistic
  AI-generated content. When posting, turn on *More options -> AI-generated content*;
  TikTok says the label does not affect distribution of content that follows its
  guidelines ([About AI-generated content](https://support.tiktok.com/en/using-tiktok/creating-videos/ai-generated-content)).
  autoshorts sends `is_aigc: true` with direct posts; for inbox drafts, turn the setting on
  yourself.
- **API limits.** Posts from TikTok apps that have not passed TikTok's audit are
  restricted to private (`SELF_ONLY`) visibility; inbox uploads allow at most 5 pending
  drafts per 24 hours ([Content Posting API](https://developers.tiktok.com/doc/content-posting-api-get-started),
  [content sharing guidelines](https://developers.tiktok.com/doc/content-sharing-guidelines)).

### How to stay monetisable with automation

Both platforms pay for original work and penalise templated volume. Use autoshorts to
remove the tedious parts, not your judgement:

1. **Pick one niche** (space, history, money habits...) and fill `topics.txt` with specific,
   interesting angles. Viewers subscribe to a theme, not to a random mix.
2. **Use a real LLM, not only the offline bank.** The offline bank is 33 fixed scripts;
   anyone else using autoshorts has the same ones.
3. **Edit and curate.** Preview scripts with `autoshorts script --topic "..."`, throw away
   weak ones, fact-check what is said (LLMs invent things), and make the prompts in
   `autoshorts/script/prompts.py` sound like you.
4. **Add something only you can add:** your own voice-over (re-record it in the YouTube or
   TikTok editor), your own footage in `assets/backgrounds/`, an opinion, a joke, a
   follow-up comment. Original commentary is what separates a channel from a template.
5. **Vary the template:** rotate formats, voices (`autoshorts voices`), caption colours and
   music. Do not post dozens of identical-looking videos a day.
6. **Post consistently, not massively.** One to three good videos a day beats twenty
   mediocre ones; the default schedule makes three.
7. **Review every video before it goes public.** That is why the defaults are private
   YouTube uploads (`upload.youtube.privacy: private`) and TikTok inbox drafts.
8. **Disclose AI use** and **only use footage and music you have the rights to**.
9. **Watch your analytics** (retention, swipe-away rate) and adjust hooks and topics.

**Be realistic:** most automated faceless channels never reach the thresholds above, and
Shorts revenue per view is small. autoshorts produces good drafts fast; growth and
earnings depend on what you do with them and are not guaranteed.

## Install

You need **Python 3.10+** (3.11 or 3.12 recommended) and **FFmpeg with libass and libx264**.
`autoshorts doctor` checks everything after installing.

### Windows 10 / 11

In PowerShell:

```powershell
winget install -e --id Python.Python.3.12
winget install -e --id Gyan.FFmpeg
winget install -e --id Git.Git
```

Close PowerShell and open a new window (so `PATH` updates), then:

```powershell
git clone https://github.com/georgemallousis-design/cla.git autoshorts
cd autoshorts
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -e ".[youtube,offline-tts]"
autoshorts doctor
```

If `Activate.ps1` is blocked ("running scripts is disabled"), run once:
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

Or let the script do all of it (installs Python/FFmpeg with winget if missing, creates the
virtualenv, runs `init` and `doctor`):

```powershell
powershell -ExecutionPolicy Bypass -File deploy\windows\install.ps1
```

Offline voices on Windows come from pyttsx3 (the built-in SAPI5 voices); espeak-ng is
optional ([installer](https://github.com/espeak-ng/espeak-ng/releases)).

### macOS

With [Homebrew](https://brew.sh):

```bash
brew install python@3.12 ffmpeg-full espeak-ng git
echo 'export PATH="$(brew --prefix ffmpeg-full)/bin:$PATH"' >> ~/.zprofile
source ~/.zprofile

git clone https://github.com/georgemallousis-design/cla.git autoshorts
cd autoshorts
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e ".[youtube,offline-tts]"
autoshorts doctor
```

Why `ffmpeg-full`: since January 2026 Homebrew's `ffmpeg` formula is a slim build without
libass, which the captions need ([Homebrew PR](https://github.com/Homebrew/homebrew-core/pull/261303)).
`ffmpeg-full` has it but is keg-only, hence the `PATH` line.

### Linux (Ubuntu / Debian)

Ubuntu 22.04+ and Debian 12+ ship a recent enough Python and an FFmpeg with libass:

```bash
sudo apt update
sudo apt install -y ffmpeg espeak-ng fonts-dejavu-core fonts-liberation python3-venv python3-pip git

git clone https://github.com/georgemallousis-design/cla.git autoshorts
cd autoshorts
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[youtube]"
autoshorts doctor
```

For a server that should run on its own, use `sudo deploy/install.sh` instead (see
[Deploying to a VPS](#deploying-to-a-vps-over-ssh)).

Optional extras: `youtube` (Google API client for uploads), `offline-tts` (pyttsx3),
`dev` (pytest). Run the tests with `pip install -e ".[dev]"` and `pytest`.

## Quickstart

```bash
autoshorts init      # creates config.yaml, .env and topics.txt here (never overwrites)
                     # optional: put free API keys in .env (see "Getting free API keys")
autoshorts doctor    # checks FFmpeg, fonts, voices, script writer, keys, uploads
autoshorts make      # makes one video into ./output/
```

`make` works with **no keys at all**: offline script bank, edge-tts voice (or an offline
voice), generated backgrounds. Each free key you add makes the videos better:

| Add | Gets you |
|---|---|
| Ollama or `LLM_API_KEY` | scripts about any topic, in any language |
| `PEXELS_API_KEY` / `PIXABAY_API_KEY` | real stock footage instead of abstract backgrounds |
| tracks in `assets/music/` | background music |

Without an LLM, each topic is only matched loosely to the closest of the 33 offline
scripts (or a random one of the chosen format), and the topic still counts as used.

The first video takes a few minutes on a typical laptop. Watch it, read `youtube.txt` and
`tiktok.txt` in the job folder, then tune `config.yaml`.

## Everyday use

```bash
autoshorts make                                   # next topic from topics.txt
autoshorts make --topic "Why octopuses have three hearts" --format facts
autoshorts make --upload youtube,tiktok           # upload when done
autoshorts batch -n 5                             # five videos in a row (default 3)
autoshorts script --topic "How GPS works" --format quiz   # print the script JSON only
autoshorts upload latest --to youtube             # upload the newest finished video
autoshorts upload output/20261001-101500-how-gps-works --to tiktok
autoshorts auth youtube                           # one-time YouTube login
autoshorts topics list                            # your topics and which are used
autoshorts topics list --ideas                    # also the unused built-in ideas
autoshorts topics add "Why cats purr" "How bees make honey"
autoshorts voices --lang en                       # edge-tts voices (en, en-GB, es, all...)
autoshorts --help                                 # all commands; <command> --help for options
```

- `--config PATH` (or `-c`) uses another config file, `-v` turns on debug logging; both work
  before or after the command.
- Platforms: `youtube`, `tiktok`, `all`, `none` (also `yt`, `tt`).
- If `upload.youtube.enabled` / `upload.tiktok.enabled` is `true` in `config.yaml`, `make`
  and `batch` upload there automatically; `--no-upload` skips it for one run.
- Topics: the first unused line of `topics.txt` is used, and marked used only after its
  video rendered. When the file runs out, a built-in idea is picked.
- `batch` skips a failed video and continues; it stops early if the same error repeats
  three times in a row.

Exit codes (for scripts and schedulers):

| Code | Meaning |
|---|---|
| 0 | success |
| 1 | `doctor` found a FAIL (or an unexpected crash) |
| 2 | error: bad config or arguments, missing tool, the video failed |
| 3 | the video was made, but an upload (or some videos of a batch) failed |
| 130 | interrupted with Ctrl+C |

## Getting free API keys

All keys go into `.env` (created by `autoshorts init` from [.env.example](.env.example)).
Never put them in `config.yaml`.

**Pexels (stock video)** - create a free account, open <https://www.pexels.com/api/>,
request a key (describe your project in a sentence) and copy it to `PEXELS_API_KEY=`.
Default limit: 200 requests per hour, 20,000 per month. The Pexels licence allows free
commercial use without attribution; autoshorts still credits creators in `credits.txt`
and the YouTube description.

**Pixabay (stock video)** - create a free account and open <https://pixabay.com/api/docs/>;
your key is shown in the `key` parameter row. Copy it to `PIXABAY_API_KEY=`. Limit:
100 requests per 60 seconds; autoshorts caches searches for 24 hours as Pixabay requires.

**Groq (script writer, default API)** - sign in at <https://console.groq.com/keys>, create
a key and copy it to `LLM_API_KEY=`. `config.yaml` already points at Groq with
`llama-3.3-70b-versatile`. Free-tier limits are per model (see
<https://console.groq.com/settings/limits>); one script is one request plus retries.

**Google AI Studio (Gemini)** - create a key at <https://aistudio.google.com/apikey>, put
it in `LLM_API_KEY=` and change `config.yaml`:

```yaml
script:
  openai_compatible:
    base_url: https://generativelanguage.googleapis.com/v1beta/openai
    model: gemini-3.5-flash   # use a current Flash model id from https://ai.google.dev/gemini-api/docs/models
```

Gemini model names change often (the 2.0 models were shut down in June 2026), so check
the models page for the current free Flash model.

**OpenRouter** - key at <https://openrouter.ai/keys>, `base_url: https://openrouter.ai/api/v1`
and any model id that ends in `:free`.

**Ollama (local, no key, private)** - install from <https://ollama.com>, then:

```bash
ollama pull llama3.1:8b
```

Keep Ollama running; `script.provider: auto` uses it automatically when it is reachable
and the model is pulled. An 8B model wants about 8 GB of RAM; on weaker machines use a
smaller model (e.g. `ollama pull llama3.2:3b` and set `script.ollama.model`). On a small
CPU-only VPS a free API key is much faster.

## Your own backgrounds, music and fonts

### Background clips

Put videos (`.mp4 .mov .mkv .webm .m4v`) or images (`.jpg .png .webp`) in
`assets/backgrounds/`, in sub-folders if you like. Any size works: clips are cropped to
fill 9:16 and looped if short; images get a slow zoom. Clips whose file or folder names
match a segment's visual keywords are used first, so `space/nebula.mp4` or
`ocean-waves.mp4` help. To use only your own footage:

```yaml
visuals:
  providers: [local, generated]
```

Gameplay-style backgrounds work too: a folder of long clips is used for any topic.

### Background music

Drop `.mp3 .m4a .aac .wav .ogg .flac` files in `assets/music/`; one is picked at random
per video and lowered automatically while the voice speaks (`music.volume`, `music.duck`).

**Copyright warning:** only use music you have the rights to use on the platform you post
to. A claimed track can block a Short longer than one minute, mute a TikTok, or demonetise
the whole channel.

- **[YouTube Audio Library](https://support.google.com/youtube/answer/3376882)** (YouTube
  Studio -> Audio library): copyright-safe on YouTube and free in monetised videos. Some
  tracks require attribution in the description; add that yourself, or filter for tracks
  that do not.
- **[Pixabay Music](https://pixabay.com/music/)**: free licence, but some tracks are
  registered with YouTube Content ID by their uploaders and can still be claimed. Check the
  track page before using it.
- **TikTok:** the safest choice is to post without music (`music.enabled: false`) and add
  a sound from TikTok's own library in the app; inbox mode drafts make that easy.

### Fonts

Put `.ttf`/`.otf` files in `assets/fonts/` (for example Montserrat ExtraBold, Anton or
Bebas Neue from [Google Fonts](https://fonts.google.com), all free to use). With
`captions.font: auto` the boldest font found there is used; otherwise set `captions.font` to
the font's family name. Without custom fonts autoshorts picks Arial Black / Arial
(Windows), Arial Black / Helvetica (macOS) or DejaVu Sans / Liberation Sans (Linux).

## YouTube upload setup

One-time, free, about 15 minutes.

1. Open <https://console.cloud.google.com>, sign in and **create a project** (for example
   "autoshorts").
2. **APIs & Services -> Library**, search **YouTube Data API v3**, click **Enable**.
3. **OAuth consent screen** (in the newer console: **Google Auth Platform -> Branding /
   Audience**): user type **External**, fill in the app name and your email. Under
   **Test users** add the Google account that owns your YouTube channel.
4. **Credentials** (or **Clients**) -> **Create credentials -> OAuth client ID** ->
   application type **Desktop app** -> create -> **Download JSON**. Save it as
   `secrets/client_secret.json` next to your `config.yaml`.
5. Run:

   ```bash
   autoshorts auth youtube
   ```

   A browser opens; pick the channel's account. Google shows "Google hasn't verified this
   app": that is your own app, click **Continue** and allow uploads. The token is saved to
   `secrets/youtube_token.json` (keep it private).
6. Turn uploads on: `upload.youtube.enabled: true` in `config.yaml`, or pass
   `--upload youtube`. Test with `autoshorts upload latest --to youtube`.

Things to know:

- **Unaudited projects upload private, locked videos.** As explained
  [above](#youtube), uploads from new API projects stay private and cannot be made public
  until the project passes YouTube's API audit
  ([audit and quota extension form](https://support.google.com/youtube/contact/yt_api_form)).
  Until then, a good workflow is: let autoshorts render (and upload privately if you like,
  as a review copy), then upload the videos you approve yourself in YouTube Studio or the
  YouTube app using the text in `youtube.txt`.
- **Quota:** since 1 June 2026 `videos.insert` has its own quota bucket of 100 uploads per
  day per project; before that an upload cost about 100 units (1,600 before 4 December
  2025) of the general 10,000 daily units, which is where the "6 uploads a day" in older
  guides comes from ([API revision history](https://developers.google.com/youtube/v3/revision_history)).
  The quota resets at midnight Pacific Time. Your channel also has its own daily upload
  limit.
- **7-day tokens in Testing mode:** while the consent screen's publishing status is
  "Testing", Google expires the refresh token after 7 days and you must run
  `autoshorts auth youtube` again. Setting the publishing status to "In production" avoids
  that; for your own account you can click through the "unverified app" warning.
- **Custom thumbnails** need a [verified channel](https://www.youtube.com/verify); if that
  fails the upload still succeeds and a warning is logged.
- **Headless server:** run `autoshorts auth youtube` on your PC and copy
  `secrets/youtube_token.json` (and `client_secret.json`) to the server, or keep the command
  running on the server, open an SSH tunnel from your PC with
  `ssh -L 8765:localhost:8765 user@<server-ip>` and open the printed URL in your PC's browser.

## TikTok upload setup

TikTok has no "personal upload key"; you create a (free) developer app and authorise your
own account with it.

1. Sign in at <https://developers.tiktok.com> with your TikTok account and go to
   **Manage apps -> Connect an app** (create an organisation first if asked).
2. Fill in the basic app details (name, icon, category, description, platform **Web**).
3. **Add products:**
   - **Login Kit** - add a **Redirect URI**: any `https://` address you control, for example
     `https://your-site.example/tiktok-callback`. The page does not need to work; you only
     copy the code from the browser's address bar.
   - **Content Posting API** - enable **Direct Post** only if you want `mode: direct`.
   - Scopes: `user.info.basic`, `video.upload` (inbox drafts), plus `video.publish` for
     direct posts.
4. **Sandbox** (to start without app review): create a sandbox in the app, and under
   **Target users** add your TikTok account (up to 10). Use the sandbox's client key and
   secret while testing.
5. **Get the tokens.** In the folder with your `.env`:

   ```bash
   python deploy/tiktok_token.py            # inbox mode
   python deploy/tiktok_token.py --direct   # also video.publish for direct mode
   ```

   It asks for your client key, client secret and redirect URI, prints an authorisation
   link, and after you paste back the address TikTok redirected you to, writes
   `TIKTOK_ACCESS_TOKEN`, `TIKTOK_REFRESH_TOKEN`, `TIKTOK_CLIENT_KEY` and
   `TIKTOK_CLIENT_SECRET` to `.env`. Access tokens last 24 hours and refresh tokens 365
   days; with all four set, autoshorts renews the access token by itself
   ([token management](https://developers.tiktok.com/doc/login-kit-manage-user-access-tokens)).
   `python deploy/tiktok_token.py --refresh` renews and saves them manually.
6. Enable uploads: `upload.tiktok.enabled: true` (or `--upload tiktok`).

The two modes (`upload.tiktok.mode`):

- **`inbox` (default, recommended):** the video arrives as a draft in the TikTok app (you
  get a notification). Open it, paste the caption from `tiktok.txt`, optionally add a TikTok
  sound, turn on **AI-generated content**, and post. Works for any app without an audit;
  at most 5 pending drafts per 24 hours.
- **`direct`:** posts immediately with `upload.tiktok.privacy_level`. Until TikTok audits
  your app, posts are private (`SELF_ONLY`) only, and TikTok may require the posting
  account itself to be private. The audit checks your app against TikTok's
  [content sharing guidelines](https://developers.tiktok.com/doc/content-sharing-guidelines),
  which assume an app where the user previews each post and chooses its privacy, so a
  fully automatic personal script is unlikely to qualify. Inbox mode is the realistic choice.

## Automation

The scheduled job runs `autoshorts batch -n 1 --upload youtube` three times a day. Change
the command to fit: `--upload youtube,tiktok`, or `--no-upload` to render only and publish
the best videos by hand (the sensible choice while your YouTube project is unaudited, see
[above](#youtube-upload-setup)).

### Linux: systemd timer (recommended)

`sudo deploy/install.sh` installs [deploy/autoshorts.service](deploy/autoshorts.service) and
[deploy/autoshorts.timer](deploy/autoshorts.timer) (08:00, 14:00 and 20:00 server time,
plus a random delay of up to 20 minutes). After a successful test run:

```bash
sudo systemctl start autoshorts.service        # one run now
journalctl -u autoshorts.service -e            # its log
sudo systemctl enable --now autoshorts.timer   # 3 runs a day from now on
systemctl list-timers autoshorts.timer         # next run
sudo systemctl edit --full autoshorts.service  # change the command
```

### Linux: cron (alternative)

[deploy/crontab.example](deploy/crontab.example) has the same schedule with a lock against
overlapping runs and a log in `output/cron.log`:

```bash
sudo crontab -u autoshorts /opt/autoshorts/deploy/crontab.example
```

### Windows: Task Scheduler

```powershell
powershell -ExecutionPolicy Bypass -File deploy\windows\schedule.ps1
powershell -ExecutionPolicy Bypass -File deploy\windows\schedule.ps1 -At 09:00,18:00 -Upload youtube,tiktok
Start-ScheduledTask -TaskName autoshorts     # test it now
powershell -ExecutionPolicy Bypass -File deploy\windows\schedule.ps1 -Remove
```

[deploy/windows/schedule.ps1](deploy/windows/schedule.ps1) registers a task "autoshorts"
that runs `.venv\Scripts\autoshorts.exe batch -n 1 --upload youtube` daily at 08:00, 14:00
and 20:00 and appends its output to `output\scheduler.log`. By default it runs only while
you are signed in; add `-WhenLoggedOff` (from an administrator PowerShell) to run it while
signed out. The PC has to be on and awake at those times.

## Deploying to a VPS over SSH

Any small Linux VPS works (2 vCPU and 2-4 GB RAM are plenty when the script writer is a
free API rather than local Ollama). Expect a few minutes of rendering per video; set
`video.preset: veryfast` on slow machines. Replace `<server-ip>` with your server's
address. From Windows PowerShell:

```powershell
ssh -i $env:USERPROFILE\.ssh\id_ed25519 root@<server-ip>
```

On the server (Ubuntu 22.04/24.04 or Debian 12), first create a normal admin user so you
do not work as root:

```bash
apt update && apt -y upgrade
adduser deploy
usermod -aG sudo deploy
rsync --archive --chown=deploy:deploy ~/.ssh /home/deploy
```

Reconnect as that user (`ssh -i $env:USERPROFILE\.ssh\id_ed25519 deploy@<server-ip>`),
then install:

```bash
sudo git clone https://github.com/georgemallousis-design/cla.git /opt/autoshorts
sudo /opt/autoshorts/deploy/install.sh
```

If the repository is private, clone with a GitHub token or copy it from your PC instead
(`git archive --format=tar -o autoshorts.tar HEAD` on the PC, `scp` the tar, then
`sudo mkdir /opt/autoshorts && sudo tar -xf autoshorts.tar -C /opt/autoshorts`).

[deploy/install.sh](deploy/install.sh) installs the apt packages, creates a system user
`autoshorts` that owns `/opt/autoshorts`, a virtualenv with autoshorts, runs
`autoshorts init`, installs the systemd units (not enabled yet) and a `/usr/local/bin/autoshorts`
wrapper that always runs as that user in that folder. So from any admin shell:

```bash
sudo nano /opt/autoshorts/.env        # API keys
autoshorts doctor
autoshorts make                        # test video in /opt/autoshorts/output/
```

Copy your YouTube credentials from the PC where you ran `autoshorts auth youtube`
(PowerShell, in your local autoshorts folder):

```powershell
scp -i $env:USERPROFILE\.ssh\id_ed25519 -r .\secrets deploy@<server-ip>:/tmp/autoshorts-secrets
ssh -t -i $env:USERPROFILE\.ssh\id_ed25519 deploy@<server-ip> "sudo mkdir -p /opt/autoshorts/secrets && sudo cp /tmp/autoshorts-secrets/* /opt/autoshorts/secrets/ && sudo chown -R autoshorts:autoshorts /opt/autoshorts/secrets && sudo chmod 700 /opt/autoshorts/secrets && rm -rf /tmp/autoshorts-secrets"
```

Then enable the timer (see [Automation](#automation)) and download finished videos with
`scp -i $env:USERPROFILE\.ssh\id_ed25519 -r deploy@<server-ip>:/opt/autoshorts/output/<job> .`

Updating later: `sudo -u autoshorts git -C /opt/autoshorts pull && sudo /opt/autoshorts/deploy/install.sh`.

Basic hardening once the `deploy` user works: disable root and password logins
(`PermitRootLogin no` and `PasswordAuthentication no` in `/etc/ssh/sshd_config`, then
`sudo systemctl reload ssh`) and enable the firewall (`sudo ufw allow OpenSSH && sudo ufw enable`).
Note that edge-tts is sometimes blocked from datacenter IP addresses; autoshorts then uses
espeak-ng, which sounds robotic, so check `autoshorts doctor` and the first video's voice.

## Docker

The image contains Python, FFmpeg (with libass/libx264), espeak-ng and fonts. Your
config, keys, assets and videos live in a mounted folder.

```bash
docker build -t autoshorts .
mkdir data
docker run --rm -v "$PWD/data:/app/data" autoshorts init
# edit data/.env and data/config.yaml, add data/assets/music etc.
docker run --rm -v "$PWD/data:/app/data" autoshorts doctor
docker run --rm -v "$PWD/data:/app/data" autoshorts make
docker run --rm -v "$PWD/data:/app/data" autoshorts batch -n 1 --upload youtube
```

- PowerShell: use `-v "${PWD}\data:/app/data"`.
- The container runs as uid 1000. On Linux, if your user has another uid, add
  `--user "$(id -u):$(id -g)"`.
- YouTube: run `autoshorts auth youtube` on a machine with a browser (not in the
  container) and put `client_secret.json` and `youtube_token.json` in `data/secrets/`.
- To reach Ollama on the host, set `script.ollama.base_url` to
  `http://host.docker.internal:11434` (Docker Desktop; on Linux also add
  `--add-host=host.docker.internal:host-gateway`).
- Schedule it with the host's cron, for example
  `0 8,14,20 * * * docker run --rm -v /srv/autoshorts:/app/data autoshorts batch -n 1 --upload youtube`.

## Configuration

Everything is in `config.yaml`; [config.example.yaml](config.example.yaml) lists every
setting with its default and a comment. Relative paths are relative to the config file.
Settings people change most:

| Setting | What it does |
|---|---|
| `script.provider` / `script.format` | which script writer; which format (or `random`) |
| `script.language` + `tts.edge.voice` | write and speak another language, e.g. `es` + `es-ES-AlvaroNeural` |
| `tts.edge.voice`, `tts.edge.rate` | voice and speed (`autoshorts voices`) |
| `video.target_seconds` | aimed length (default 65 s: over 1 minute for TikTok rewards) |
| `video.preset` | `veryfast` renders much faster on weak machines |
| `visuals.providers` | footage sources in order |
| `captions.*` | font, size, colours, position, words per caption |
| `music.volume`, `music.duck` | music level |
| `upload.youtube.privacy`, `upload.tiktok.mode` | how uploads are published |
| `keep_intermediate` | keep `work/` (audio, shots) for debugging |

Secrets live only in `.env` (see [.env.example](.env.example)); settings ending in `_env`
name the variable to read.

```
  visuals/          footage: pexels.py, pixabay.py, local.py, generated.py

  render.py         FFmpeg rendering and thumbnail

  upload/           youtube.py, tiktok.py
  data/             content_bank.json (offline scripts), topic_ideas.txt

```

Created at runtime next to `config.yaml`: `output/` (videos), `cache/` (downloaded and
generated clips, safe to delete), `state/` (used topics), `secrets/` (OAuth files).

## Troubleshooting

Start with `autoshorts doctor`; it prints a hint for each problem. For any failed video,
`error.txt` in its job folder has the details, and `-v` shows debug logs.

| Problem | Fix |
|---|---|
| `ffmpeg` not found (Windows) | Open a **new** terminal after `winget install Gyan.FFmpeg`. Check with `where.exe ffmpeg`; winget puts it in `%LOCALAPPDATA%\Microsoft\WinGet\Links`, which must be on `PATH`. |
| `No such filter: 'subtitles'` / doctor says libass FAIL | Your FFmpeg lacks libass. Linux: the distro `ffmpeg` package has it. macOS: `brew install ffmpeg-full` (see [macOS](#macos)). Windows: the Gyan builds have it. |
| edge-tts errors (403, timeouts, no voice) | Microsoft blocks or changes the service now and then, especially for datacenter IPs. `auto` mode falls back to pyttsx3/espeak by itself (after about 6 s of retries). Try `pip install -U edge-tts`; set `tts.provider: espeak` (or `pyttsx3`) to skip edge entirely. |
| Captions in a plain or wrong font | `doctor` shows the font in use. Linux: `sudo apt install fonts-dejavu-core`. Or put a `.ttf` in `assets/fonts/` and set `captions.font` to its family name (`fc-list : family` lists names). |
| "Ollama is not reachable" / model missing | Start Ollama and run `ollama pull llama3.1:8b`, or use a free API key. In `auto` mode autoshorts falls back to the offline bank with a warning. |
| Script writer 401 / 429 | 401: wrong `LLM_API_KEY` or `base_url`. 429: free-tier rate limit; wait, make fewer videos per hour, or switch provider. |
| Only abstract backgrounds | No stock keys set (check `doctor`), or the provider's rate limit was hit. Add keys or your own clips. |
| Same offline script topics again | The offline bank has 33 scripts. Set up Ollama or an API key for unlimited topics. |
| YouTube `quotaExceeded` | Daily upload quota used up; it resets at midnight Pacific Time. |
| YouTube token expired after a week | Consent screen in "Testing" mode; run `autoshorts auth youtube` again or set it to "In production". |
| YouTube video "locked as private" | Unaudited API project; see [YouTube upload setup](#youtube-upload-setup). |
| TikTok `access_token_invalid` | Run `python deploy/tiktok_token.py --refresh` (or set all four `TIKTOK_*` values so autoshorts refreshes by itself). |
| TikTok `spam_risk_too_many_pending_share` | More than 5 drafts waiting; post or delete them in the app. |
| TikTok `unaudited_client_can_only_post_to_private_accounts` | Use `mode: inbox`, or make the account private for direct posts. |
| Rendering is slow | `video.preset: veryfast`; stock video renders faster than still images; avoid running Ollama on the same small server. |
| Windows: "running scripts is disabled" | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, or run scripts with `powershell -ExecutionPolicy Bypass -File ...`. |

## FAQ

**Is it really free?** Yes. Everything it uses is free (open-source tools, free API tiers,
free platform APIs). Optional costs are your own: a VPS if you want it running 24/7, or
paid API tiers if you outgrow the free ones.

**Do I need a GPU?** No. Rendering uses the CPU. A GPU only helps if you run Ollama locally.

**Will it post publicly on its own?** Only after both platforms have audited your API
project/app. Until then YouTube API uploads are private and TikTok gets drafts or private
posts. Reviewing each video before it goes public is a good idea anyway.

**How many videos a day?** One to three. The quotas allow more, but volume without
quality is exactly what the "inauthentic content" rules target.

**Can I use my own voice?** Not built in yet. You can re-record the voice-over in the
YouTube or TikTok editor, or use a different edge voice per video.

**Can I edit a script before it is rendered?** Not in one step yet. Preview with
`autoshorts script`, regenerate until you like it, and change the style for good in
`autoshorts/script/prompts.py`.

**Other languages?** Set `script.language` and a matching `tts.edge.voice` (list them
with `autoshorts voices --lang es`). This needs an LLM; the offline bank is English only,
and hashtags are limited to Latin letters and digits.

**Longer videos?** `video.max_seconds` caps the length at 175 s so videos stay valid
Shorts (YouTube allows up to 3 minutes); `video.target_seconds` sets the aimed length.

**Where did my video go?** `output/<date>-<topic>/video.mp4`; the command prints the path.
`autoshorts upload latest` uploads the newest one.
